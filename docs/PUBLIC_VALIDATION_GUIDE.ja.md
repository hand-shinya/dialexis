# 公開第三者検証ガイド

更新日：2026-08-27

## 目的

Dialexis は、URLを知っている人がログインやAPIキーなしで、同じ探索・失敗時の説明・次の行動を再現できる公開研究レンズとして検証する。ここで確認するのは、第一に「操作が止まらず、意味のある次の行動につながるか」、第二に「候補・証拠・解釈・未確認が混ざっていないか」である。

## 現在の公開状態

- 検証URL：`http://219.94.244.239:8000/`
- 公開状態：IP直打ちのHTTP検証版
- 利用方法：ログイン不要、中心探索はAPIキー不要
- データ状態：匿名ブラウザごとの署名ワークスペース。非公開の研究台帳・プロジェクト・監視対象は他のブラウザから見えず、公開設定した台帳・プロジェクトだけが第三者に読取・引用可能
- 公開資産の扱い：第三者は閲覧・引用・エクスポートできるが、所有者以外は編集できない。公開台帳は自分のプロジェクトへ参照接続するか、分岐して編集する
- 入力禁止：個人情報、非公開資料、秘密のAPIキー

HTTPのままでは通信相手の認証と暗号化が成立しない。したがって、スマートフォン表示の検証は可能だが、広い告知とAPIキーを使う本格運用の前に、ドメイン・DNS・TLS証明書・HTTP→HTTPSリダイレクトを完了させる。

## 5分検証シナリオ

1. `/validation?lang=ja` を開き、画面の手順を読む。
2. `Karl Marx` を検索する。
3. 人物として認識され、人物同定・著作・概念・受容の層が出ることを確認する。
4. `吉本隆明` などの関連人物を選び、先頭メニューの「中心命題との関係」を開く。
5. `共産党宣言` を選び、「著作の系譜」を開く。原題、成立条件、後続の問いが出ることを確認する。
6. 「別の語と組み合わせる」で `吉本隆明` を入力し、AND検索を実行する。結果が空でも、停止せず、未取得・未確認の説明と次の入口が残ることを確認する。
7. `非有機的肉体` を検索し、語・原語・翻訳・受容史、候補と証拠の区別を確認する。
8. 同じ手順をスマートフォンの縦画面で行う。メニュー、処理中表示、閉じる、戻る、次の提案が画面外に逃げないことを確認する。
9. ブラウザのプライベートウィンドウ等、別のブラウザプロファイルで `/desk` を開く。最初のプロファイルで作成した非公開台帳・プロジェクトが見えず、公開した資産だけが閲覧専用で見えることを確認する。

## 合格条件

- 途中で空白画面や永続的な待機状態にならない。
- APIや外部情報源の遅延時に、処理中であることが見える。
- 空結果・失敗・未確認が成功結果のように表示されない。
- 失敗した場合にも、検索・別の見方・語の再中心化など次の行動が提示される。
- 人物名を一般語の語源として誤認しない。
- 著作の系譜は、著作名・原題・年代・成立条件・後続の問いを分けて表示する。
- スマートフォン幅で横スクロールの破綻がなく、主要ボタンをタップできる。
- 別プロファイルで非公開資産が混入せず、公開資産には編集操作が表示されない。
- 失敗時にページ全体が停止せず、現在の条件、原因の種類、再試行または別の入口が残る。

## 報告フォーマット

```text

端末／OS／ブラウザ：
縦・横：
URLと入力語：
操作列：
表示された結果：
処理時間・空結果・エラー：
次の行動は提示されたか：
理解が深まった点：

スクリーンショット／録画：
```

報告先は [GitHub Issues](https://github.com/hand-shinya/dialexis/issues)。公開URL・時刻・操作列を添え、APIキーや個人情報は貼らない。

## 判定の限界

自動抽出は証拠ではなく候補であり、グラフは真理の地図ではなく探索レンズである。UIが壊れないことは、原典の意味・翻訳の正確さ・引用や影響関係が確定したことを意味しない。後者は原典、版、訳者、標準ロケータ、本文引用を人間が照合する。
