00-A

設計を縛る七公理

機能を増やす前に、何を保存し、何を棄却し、何を上位概念へ持ち上げるかを決める憲法層。

AXIOM 01
問いの変換

知識を消費させず、利用者の問いをより深い問いへ変換する。

棄却：答えだけで終了するUI
AXIOM 02
使用即貢献

一人で使っても価値があり、利用の痕跡が将来の公共土壌になる。

棄却：コミュニティ参加を前提にする
AXIOM 03
レンズ原理

百科事典を内部に溜めず、外部の生きた情報源へ接続する。

棄却：静的な知識DB
AXIOM 04
鮮度の刻印

外部情報には出所と取得時刻を付け、古さを沈黙させない。

棄却：時刻のない要約
AXIOM 05
退化階梯

全機能に無料・鍵不要・決定論的なLevel 0を持たせ、鍵は昇格だけに使う。

棄却：LLMキー必須の基盤
AXIOM 06
AI透明性

AIが触れた出力は明示・台帳記録・確度分類し、人間確認まで未確認にする。

棄却：AI出力を地の文へ混ぜる
AXIOM 07
撤退可能性

Markdown / JSON-LD / BibTeX / CSL JSONへ持ち出し、サイト消滅後も研究を残す。

棄却：独自形式ロックイン

検索・台帳・プロジェクトの三分法

「検索結果」と「研究資産」を同じものにしないことが、Dialexisの価値を守る構造上の核心です。

現在の結果を探索する

入力語から外部情報源を照会し、Map・意味単位・多言語・人物・著作・組み合わせを表示します。通常は永続保存しません。

  • 例外 → Map / Contextを保持
  • 人物名 → 一般語の語源検索へ落とさない

翻訳・受容史を研究資産へ昇格

原語・訳語・版・訳者・引用・受容・保存／欠損／追加・反証課題・出典を証拠階層付きで保持します。

台帳は独立した共有資産

candidate ≠ confirmed source ≠ interpretation

入力は終点ではありません。中心語を定義し、Mapから次の操作を選び、結果を研究過程へ接続します。

成功時の共通契約

07

前編・後編と残課題

いま完成させるべき核と、構造だけ先に用意して本実装を後ろへ送る領域を切り分ける。

現行の中心

P0意味単位の語彙・境界を増やし、文字分解を補助層に保つ。
P0Menu / Actionの処理中表示と失敗説明を全Actionへ適用する。
P1原典・版・訳者・標準ロケータを台帳の第一級項目として埋める。
P1人物・著作・概念・受容者を本文引用と影響関係へ接地する。

前編の受入条件

守る候補／証拠／解釈／判断の区別。
守る台帳とプロジェクトの多対多再利用。
守る外部源の取得時刻・error・fallback。
測る人間が「次に何を確認するか」を説明できるか。

長文入口だけ先に設計

入力単位をtermだけに固定せず、将来の文・段落・引用を同じ研究台帳へ接続できる構造にする。

subject_type = textsource_textanchor_terms[]author / work / editionlocator

本実装は後編

未実装文章からの重要語抽出と前後文脈の構造化。
未実装原典全文・版比較・用例・翻訳アラインメント。
未実装論証再構成と、複数語の収束した説明。
原則自動抽出した語を即座に研究事実へ格上げしない。

情報源と偏り

P2TEI / IIIF / PhilPapers、非西洋の中国・インド・イスラーム系情報源。
P2文化圏・情報源の偏りの測定。
P2重力代理指標を引用・コーパス・意味関係の出所付き信号へ分解。

公開品質

必要ドメイン・HTTPS・HSTS・バックアップ復元検証。
必要実機ブラウザのタッチ操作と低速回線の人間検証。
未検証知的好奇心や理解深化の定量的効果。
